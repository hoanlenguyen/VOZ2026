# VOZ – My Sports World

Hackathon app (Kaleva Media "Beyond the Scoreboard"): AI-driven, personalised **multi-sport** news.
Today: ice hockey (Liiga) and football (football-data.org). New sports and leagues plug in as providers.
Nuxt 4 full stack; API keys live in `.env` (gitignored) and are only used server-side.

## Commands
- `npm run dev` — dev server (stop it before restarting; Nuxt refuses a second instance). After adding a new component, restart if SSR logs "Failed to resolve component".
  Changing `.env` or `nuxt.config.ts` makes the server restart itself; a second dev server of this folder (e.g. an old `--port 3002`) blocks that restart and every request then returns 500 "Another Nuxt dev server is already running".
- `npm run typecheck` — must pass before committing
- Never hand-edit or prune `package-lock.json`: CI runs `npm ci` on Linux, which fails if optional/peer entries (e.g. `@emnapi/*` for sharp's wasm build) are missing even though a Windows install works. Regenerate with `npm install --package-lock-only` and check with `npm ci` in a clean folder.
- `npm test` — story checker tests (Node's test runner, plain TS); also run by the deploy workflow
- `npm run snapshot -- [--only liiga|football-data] [--details] [--competitions PL,BL1]` — save upstream
  responses to `data/snapshots/<provider>/` for offline demos (football: ~6.5 s per request, free-plan limit)

## Deployment
- Cloudflare Workers, auto-deployed by `.github/workflows/deploy.yml` on push to `main` (typecheck → build → `wrangler deploy`).
- Nitro preset `cloudflare_module` (nuxt.config); Worker config in `wrangler.jsonc` (`deployConfig: false`, so this file is the only config).
- Workers has no filesystem: snapshots are Nitro server assets (`useStorage('assets:snapshots')`); per-game Liiga files are excluded from the bundle.
- API keys are Worker secrets uploaded by the workflow from GitHub secrets; new secrets must be added to the workflow's `secrets:` list and `env:` block.
- Read env only inside request handlers (Workers provides it per request). Local Workers test: `npm run preview` with `.dev.vars`.
- Keep `compatibility_date` within what the pinned wrangler's runtime supports (wrangler 4.152.0 ⇒ 2026-10-01 works).

## Environment (`.env`, see `.env.example`)
- `NUXT_LIIGA_API_KEY` — Liiga stats API, sent as `x-api-key`
- `NUXT_FOOTBALL_DATA_TOKEN` — football-data.org, sent as `X-Auth-Token`; free plan = TIER_ONE competitions, 10 requests/minute
- `NUXT_GNEWS_API_KEY` — GNews headline search (sent as `apikey` query param, redacted from errors); free plan 100 requests/day, ~1 request/s
- `NUXT_OPENAI_API_KEY` — OpenAI Responses API for AI match stories, AI headlines and the headline translation agent (reasoning effort `low`; `NUXT_STORY_REASONING_EFFORT` overrides)
- `NUXT_OPENAI_MODEL` — model for all agents (stories, headlines, translation), as an API id (`gpt-6-luna`, the default) or a display name (`GPT-6 Luna`); `llmConfig()` converts names to ids via `shared/utils/model-name.ts`, and the story label shows the display name. Production value lives in `wrangler.jsonc` vars. Story cache keys include the model, and pre-written stories are only reused by the model that wrote them (unless there is no API key); after switching, re-run `npm run warm:stories` to pre-write the new model's stories.
- `NUXT_OPENAI_TTS_MODEL` (default `gpt-4o-mini-tts`), `NUXT_PODCAST_VOICE` (default `marin`) — text to speech for the AI podcasts; the podcast script is written by `NUXT_OPENAI_MODEL`
- `NUXT_DATA_MODE=live|auto|snapshot` — upstream only / upstream with snapshot fallback / offline only

## Architecture
- `shared/types/sports.ts` — sport-agnostic types (Competition, TeamListItem, Match, ScoringEvent, StandingRow). The app and AI work only with these.
- `shared/utils/competitions.ts` — every competition we cover; adding a league of an existing provider is one entry
- `server/providers/<provider>.ts` — one per data source; implements `SportProvider` (`server/providers/types.ts`) and maps raw JSON → shared types
- `server/utils/upstream.ts` — the only place that calls external APIs (`UpstreamId` = sports providers + `gnews`): keys, cache, rate limit, snapshot fallback. Query-string keys go in `authQuery` so they never reach cache keys, snapshot names or logs.
- `server/utils/sports.ts` — provider registry and the `[competition]` route helper
- API: `/api/landing`, `/api/competitions`, `/api/competitions/:competition/{teams,standings,matches,matches/:id,matches/:id/press,matches/:id/story,matches/:id/headline}`, `/api/podcasts`, `/api/podcasts/:id/audio`, `/api/health`, dev-only `/api/raw/:provider/*`. Every route that returns text takes `?lang=en|fi`.
- `server/utils/compare.ts` — match-page comparison (a finished match: one "Match stats" group = score by period + `MatchTeam.stats`, plus earlier meetings; an upcoming one: before kick-off, last five, meetings): goals by period, `MatchTeam.stats` (Liiga: shots, puck control, faceoffs, passes, PIM, … from `games/{season}/{id}/stats`), and both teams' season record before kick-off counted from results (points/goals reconcile with the official tables); returned as `compare` by `/api/competitions/:competition/matches/:id`. Labels and notes per language in `server/utils/compare-text.ts` (row label key = row id / stats key)
- `server/utils/press.ts` — "What the press says": GNews search by both team names (ASCII-folded; GNews rejects non-ASCII) in a window around kick-off, kept only if headline/description names both teams; returns headline, source, link only (never description/content/images). Endpoint `/api/competitions/:competition/matches/:id/press`, loaded client-side by `NewsPressCard`.
- `server/utils/mock-matches.ts` — mock "deep data" matches from `data/mock/<competition>/<id>.json` (server assets `mocks`, bundled on Workers): full match-centre facts (key events, line-ups, stats, structured event list). Mapped to `Match` + `MatchDetailExtras` (`shared/types/match-detail.ts`: timeline, line-ups, referee, source). Teams resolve to the provider's team keys/crests by name; the provider's record of the same game (same teams + UTC day) is replaced on the front page, and both ids serve the mock detail. Mocks always appear on the front page and lead their league. Store facts only, never another outlet's written commentary; labels are written in code.
- `server/utils/translate.ts` — AI translation agent `translateTexts(texts, lang)` for text VOZ doesn't write; today only the press headlines (`press.ts`). Uses the shared OpenAI client `respond()` (`server/utils/llm.ts`, no tools); without a key, headlines stay untranslated. Never use it for VOZ's own stories or labels (those are templates / i18n).
  - Cache: `kvcache` key `tr:v1:<lang>:<model>:<sha256>`, 30 days; concurrent requests share one in-flight call; all uncached texts of a request go in one chat call.
  - `keepsNumbers()` guard: a translation must keep the original's digit groups; otherwise the original is shown and nothing is cached. Any failure returns the originals.
  - UI: `PressArticle.translated` / `originalTitle`; the card shows "Translated automatically" / "Konekäännös" and the original on hover.
  - The Responses output is a `reasoning` item, then a `message` item whose `output_text` is the JSON `{"translations": [...]}` (parsed from the first `{`). About 150 output tokens for a few headlines at reasoning effort low.
- AI match stories (single agent + harness):
  - `server/utils/facts.ts` — fact ledger f1…fN for a match (result, timeline, stats, form, table, h2h, context), computed from Match / extras / season results. Name teams as the match does.
  - `shared/utils/story-check.ts` — checker: every number (rounding allowed) and every person named must appear in the facts a sentence cites; no quotes, speech or injuries; word range per length. Pure TS, tested in `tests/` (`npm test`).
  - `server/utils/story-agent.ts` — agent with tools `get_facts`, `check_story`, `submit_story` (`tool_choice: required`); harness: 8 turns / 90 s, final re-check, trace, template fallback. `server/utils/llm.ts` — fetch-based Responses API client (one retry on 429/5xx, key never in errors).
  - `server/utils/story-cache.ts` — memory → KV (`kvcache`) → bundled `data/stories/` (re-checked against today's facts) → agent; in-flight dedupe; only checked agent stories are cached. Key includes a hash of the facts, model and prompt version.
  - `GET /api/competitions/:competition/matches/:id/story?length=short|standard|long&tone=neutral|home-fan|away-fan|analyst&lang=en|fi` (`&fresh=1` in dev regenerates). UI: `NewsMatchStory` on match pages with full data (all labels via i18n `matchStory.*`); readers get the version the newsroom published, so the length/tone switches live in the newsroom editor (`NewsStoryFormat`).
  - Finnish: the agent writes Finnish directly from the English facts (team names in basic form); the checker takes `lang` (`LENGTH_WORDS_FI`, about 20 % fewer words; Finnish number, speech and injury words; Finnish decimals need a comma, `pointDecimal()`). The template fallback is the English facts (`lang: 'en'`). English cache keys and files keep their old names; Finnish adds `.fi` (`short-neutral.fi.json`).
  - `npm run warm:stories -- --base http://localhost:3000 --match premier-league/2645271 [--lang en,fi]` (signs in as newsroom@demo.com, the only account that may request every version) pre-writes all 12 story variants per language into `data/stories/` and the AI headline per language into `data/headlines/<competition>/<id>.<lang>.json` for the demo; it needs a real key (or `--base` = the deployed site, which has one). Re-run after changing facts or prompts, then commit.
  - Rules when changing it: never let the harness publish text that failed `checkStory`; bump `PROMPT_VERSION` in `story-cache.ts` after changing the agent's instructions or tools (it invalidates cached stories); keep facts in the match's own team names and with original capitalisation (the checker matches names case-insensitively, but readers see the fact text); add a test in `tests/` for every new checker rule.
  - Stories show only on match pages with full data (`data.extras`), i.e. mock matches today. Cost per version ≈ $0.001 (3 turns, ~5k tokens in / 700 out).
  - Before reading the OpenAI API shape from memory, check the docs: Responses API `/v1/responses`, `tool_choice: required`, function outputs as `function_call_output` items, reasoning/call items passed back verbatim, `store: false`.
- AI headlines (title + subtitle for every match post: front-page cards and the match page hero):
  - Facts: `buildFacts()` plus `buildEdgeFacts()` (`server/utils/facts.ts`, section `edge`): each side's advantage worked out in code so the model never does arithmetic: table rank and points gap before kick-off, points from the last 5, win/unbeaten/losing runs (only when ≥3/≥4/≥3), goals for/against per game, goal difference, home record v away record, this season's meetings, and for results: came from behind, late decisive goal, win against the table (≥4 places) or against xG, revenge for the previous meeting. Season records reuse `seasonRecord()` / `matchOutcome()` from `compare.ts` (Liiga points). History is this season only. Hockey drops buildFacts' `form` facts (3/1/0 points) in favour of the edge facts.
  - Writer: `server/utils/headline-agent.ts`, one Responses call per match and language (no tools, JSON `{headline, subtitle, facts}`), checked by `checkHeadline()`; one retry with the issues, then null. Writes Finnish directly (team names in basic form), not via translation. Own rate limit 30 calls/min.
  - Checker: `shared/utils/headline-check.ts` (tests in `tests/headline-check.test.ts`): numbers (incl. English and Finnish number words, so "two sides" fails) and people must be in the cited facts; at least one team named as written; title 3–14 words, subtitle 8–40; no quotes, speech, injuries, clickbait, questions, more than one "!", or capitals; Finnish decimals with a comma ("2,29"); claim words (record, history, streak, unbeaten, comeback, upset, revenge, late winner, top of the table; en + fi) need a cited fact that states them (`CLAIMS`). Add a test for every new rule.
  - Cache (one for both pages, so everything generated is reused): memory → `kvcache` → bundled `data/headlines/` (server assets `headlines`; used only for the same match `state` and model, or any model without a key, while its cited facts read the same and it passes the check); `kvcache` key `hl:<HEADLINE_PROMPT_VERSION>:<lang>:<model>:<competition>:<matchId>:<state>`; state = final score for finished games (landing list and match page agree even when one has more detail), hash of the edge facts for upcoming ones. TTL 30 days finished / 2 days upcoming. The stored headline carries its cited facts (`evidence`). Bump `HEADLINE_PROMPT_VERSION` after changing the instructions or the facts the writer gets.
  - `/api/landing` never waits for the model: cached headlines replace the template (`Story.headline`, `subtitle`, `headlineOrigin: 'agent'`); the first 12 missing ones (in ranking order) are written in the background (`event.waitUntil`), so the next load shows them. `GET /api/competitions/:competition/matches/:id/headline?lang=` writes on demand (`&fresh=1` in dev); `headline: null` = keep the score title.
  - UI: `StoryCard` shows one title and one detail (the AI subtitle, else the summary; at most two lines) and a small outlined "AI content" tag in the kicker. Matches with a match story use the published story instead (headline + opening, from the cache only: `publishedMatchStory()` in `story-edits.ts`), so the card and the match page carry the same title. The match page reads as the story: image (cover or match graphic), the story headline as the title, a byline (competition and matchday, date, author), then the story text; the AI headline desk is not shown there. `keepScoresTogether()` (`shared/utils/format.ts`) stops "1–1" wrapping in free text.
  - Without `NUXT_OPENAI_API_KEY` nothing changes (template titles). Local test without a key: point `NUXT_OPENAI_BASE_URL` at a fake Responses server.
- AI podcasts (20–30 second audio bulletins about one match, team or league):
  - Subjects (`shared/types/podcast.ts`): `match` (made by the newsroom: "Generate podcast" on the match page), `team` and `league` (daily). Ids `podcastSubjectId()` (`shared/utils/podcast.ts`): `match-premier-league-2645271`, `team-premier-league-349`, `league-liiga`; episode id `<subject>.<lang>` (match) or `<subject>.<YYYY-MM-DD Helsinki>.<lang>` (daily).
  - Facts: `server/utils/podcast-subjects.ts` — match: `matchFacts()` (`facts.ts`, the headline desk's facts); team: its latest result's `matchFacts()` + current table place + next game; league: the latest round's results (≤5 within 4 days, scorers when known), top 3 of the table, the next 3 fixtures. Mock deep-data matches replace the provider's record.
  - Writer: `server/utils/podcast-agent.ts`, one Responses call (no tools, JSON `{title, sentences: [{text, facts}]}`), checked by `checkStory()` with `words` = `PODCAST_WORDS` (en 38–54, fi 26–34: English TTS ~2.6 words/s, Finnish ~1.4); one retry with the issues, else 422 and no episode. Spoken intro/outro are fixed per language (the outro is a buffer: the TTS model sometimes drops the last line). Bump `PODCAST_PROMPT_VERSION` after changing the instructions, facts or intro/outro.
  - Voice: `server/utils/tts.ts`, OpenAI `/v1/audio/speech` (`NUXT_OPENAI_TTS_MODEL`, default `gpt-4o-mini-tts`; `NUXT_PODCAST_VOICE`, default `marin`), MP3 (128 kbps mono). "VOZ" is sent as "Voz" (read as a word). Length from the file (`mp3Duration()`, `shared/utils/mp3.ts`); over 30 s it is read again faster (`speed` ≤ 1.15). OpenAI shuts these TTS models down on 2027-01-06 (successor: Realtime API); bundled demo audio keeps working.
  - Store: `kvcache` `podcast:ep:<id>`, `podcast:audio:<id>` (base64), `podcast:index` (newest 60: id, subject, lang, time), `podcast:latest:<subject>:<lang>`, `podcast:schedule`, `podcast:lastrun`; TTL 120 days. A daily episode is only made when the facts hash (facts + model + voice + prompt version) changed since the subject's latest one. Bundled demo episodes: `data/podcasts/<id>.json` (server assets `podcasts`) + `public/podcasts/<id>.mp3`, written by `npm run warm:podcasts -- [--match premier-league/2645271 | --team premier-league:349 | --league premier-league] [--lang en,fi]` (dev server + real key; verify by listening, the checker cannot hear the audio). Bundled today: the demo match, Ipswich (team) and the Premier League (league), en + fi, so the front page's Podcasts section is filled before the first scheduled run; a bundled daily episode counts as the subject's latest, so the cron skips it until the facts change.
  - Daily run: Workers cron `0 5 * * *` UTC (`wrangler.jsonc` `triggers.crons`) → Nitro `scheduledTasks` → task `podcasts:daily` (`server/tasks/podcasts/daily.ts`) → `runDailyPodcasts()`: every scheduled subject × language in turn, failures retried once at the end. Keep the cron in step in `wrangler.jsonc`, `nuxt.config.ts` and `PODCAST_CRON`. Dev: `GET /_nitro/tasks/podcasts:daily`; Workers locally: `wrangler dev --test-scheduled`, then `/cdn-cgi/handler/scheduled?cron=0+5+*+*+*`. Default schedule: Ipswich, Premier League, Liiga, en + fi.
  - Podcasts are for subscribers: `GET /api/podcasts?lang=&subject=&limit=` (newest first, KV + bundled) returns free and signed-out readers each episode locked (`lockEpisode()`: no script, facts or audio URL; the player shows a lock and the VOZ Plus invitation); `GET /api/podcasts/:id/audio` (Range requests; Safari needs them) requires premium. The bundled demo MP3s are static files under `public/podcasts/` (URL only given to subscribers, but reachable directly). Newsroom: `POST /api/newsroom/podcasts` `{subject, langs, force}` (languages in parallel, ~15 s), `GET /api/newsroom/podcasts/desk`, `PUT /api/newsroom/podcasts/schedule`, `POST /api/newsroom/podcasts/run`.
  - UI: `NewsPodcastPlayer` (play/pause, seek, transcript; the "AI content" tag and the cited facts for the newsroom only; one episode plays at a time), `NewsPodcastShelf` (front page "Podcasts", after the card row), `NewsMatchPodcast` (match page; newsroom "Generate podcast" / "Regenerate"), `NewsPodcastDesk` (`/newsroom`: daily schedule, generate now, run now, last run). Texts `podcast.*`.
- Table movement: `withMovement()` (`server/utils/standings-movement.ts`) adds `StandingRow.movement` (places since each team's last game: today's official table with every team's latest result taken off, re-ranked by points, goal difference, goals for). Teams without a finished game in our data get stable demo movement (`movementMocked`). Used by `/api/.../standings` and the landing tables; `TableWidget` shows ▲/▼/– and takes `highlight` (the match page marks its two teams). The match page keeps the article centred and puts the league table to its right from 1400 px wide, below it otherwise.
- `server/utils/stories.ts` — deterministic story templates (headline + summary) from Match/StandingRow facts; used by `/api/landing`
- Pages: `/` news front page (layout `news`, light theme), `/match/:competition/:id`, `/my-teams` (favourites), `/login`, `/account`, `/newsroom`, `/newsroom/stories/:id` (match story editor), `/onboarding`, `/status` (data-layer check); app screens use layout `default` (dark)
- Keys: team `"<competition>:<team>"` (`liiga:karpat`, `premier-league:57`), match `"<competition>:<id>"`
- `shared/utils/` must stay free of Nuxt imports: `scripts/` runs it with plain Node (type stripping)

### Adding a sport or provider
1. Add the `SportId` / `ProviderId` in `shared/types/sports.ts`
2. Add an upstream entry (base URL, auth header, cache, rate limit) in `server/utils/upstream.ts` and `scripts/snapshot.ts`
3. Write `server/providers/<name>.ts` implementing `SportProvider`; register it in `server/utils/sports.ts`
4. Add its competitions to `shared/utils/competitions.ts`
5. Check that goals reconcile with final scores across a full season before trusting the data

## Languages (English + Finnish)
- `@nuxtjs/i18n`, strategy `no_prefix`: same URLs, language from the browser on first visit, then the `voz_lang` cookie; EN | FI switcher in the header (`SiteHeader.vue`). `<html lang>` follows via `useLocaleHead()` in the layouts.
- Interface text: `i18n/locales/en.json` + `fi.json`, which must keep the same keys. Use `t()` and never hardcode English in components.
- Dates, scores and numbers: `useFormat()` (`app/composables/useFormat.ts`) → `fixture()` (time + day, `relative` today/tomorrow), `stamp()`, `score()`, `number()`. Never compare display words like "Today".
- `Lang` / `INTL_LOCALE` live in `shared/utils/format.ts`; `formatScore(m, lang)` suffixes: en `OT`, `SO`, `AET`, `pens`; fi `ja`, `vl`, `ja`, `rp.`
- Server text (stories, compare labels, timeline, press notes) is written per language. APIs read `requestLang(event)` (`server/utils/lang.ts`), and pages fetch with `query: { lang: locale }` (reactive, so switching refetches).
- Competition names and countries per language: `competitionName(c, lang)`, `competitionCountry(c, lang)` (`fi` field in `shared/utils/competitions.ts`, e.g. Mestarien liiga); `describeCompetition(def, lang)`.
- Stories: `server/utils/stories.ts` picks the facts, `server/utils/story-text/{en,fi}.ts` words them (`StoryPhrases`). Both languages must state the same numbers.
  Finnish keeps team names in the basic form (no case endings): "HIFK voittoon: K-Espoo–HIFK 0–3", "Maalit (HIFK): …".
- Code never reads display labels: use structured fields (`TimelineEvent.goalType`, `assist`, `playerOff`).
- External text (other outlets' headlines) is translated by the AI agent (`server/utils/translate.ts`), not by i18n. The press search runs in the reader's language first, then any language.

## Accounts and paywall (demo)
- Demo accounts in `data/accounts/accounts.json` (server asset `accounts`), passwords as PBKDF2-SHA256 hashes; all three use the password `demo`:
  `subscription@demo.com` (plan `subscriber`), `free@demo.com` (`free`), `newsroom@demo.com` (`newsroom`).
- `server/utils/accounts.ts`: `verifyLogin`, signed session cookie `voz_session` (HMAC with `NUXT_SESSION_SECRET`, demo secret when empty; httpOnly, 7 days), `sessionInfo(event)`, `requireEntitlement(event, 'premium' | 'newsroom')`.
  Entitlements: subscriber and newsroom = premium; newsroom also gets `/newsroom`. Ads (`entitlements.ads`) show to every reader: advertisers' posts (`NewsAdCard`: shop, event, league) under the league table on match pages plus a tall one (`NewsAdTall`) left of the article from 1400 px; on the front page the four are spread down the sidebar below the tables (`justify-content: space-between`), never inside the story list.
- API: `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`; client state via `useAccount()` (plugin `app/plugins/session.ts` loads it once; login/logout call `refreshNuxtData()`).
- The paywall is enforced on the server: for free and signed-out readers the match API sends `compare: null`, `extras: null`, `locked: [...]` (nothing when the newsroom opened the match to everyone) and a `teaser` (headline + two sentences of an already cached or pre-written AI story via `peekStory()`, never a new agent run; translated for fi). The story endpoint answers 401/403 (unless published for everyone).
  `NewsPaywall` shows the teaser fading into the subscription offer.
- Readers see only the match story text; the length/perspective switches, AI label, facts and "How this was made" in `MatchStory.vue` are newsroom tools.
- Newsroom match story editor: `/newsroom/stories/:id` (story id `r-`/`p-<matchKey>`), per language, for matches with full data. Mode `ai` (checked AI story, preview with its fact references) | `edited` (newsroom text in TinyMCE 8, self-hosted and bundled in `NewsRichEditor` (`.client`), `license_key: 'gpl'`) | `hidden`; audience `everyone` (the whole match page, i.e. story, comparison, timeline and line-ups, opens to free and signed-out readers) or `subscribers`; the published AI version (`length`, `tone`: the format switches live here, not on the match page); the match's cover image (alt text required) in place of the match graphic. "Preview" saves the unsaved settings as a one-hour draft (`POST /api/newsroom/drafts`, `kvcache` `newsroom:draft:<uuid>`) and shows the real match page in a frame with `?draft=<id>&as=subscriber|free`: for newsroom sessions only, `readerContext()` (`story-edits.ts`) applies the draft and simulates that reader in the match API and story endpoint (timeline, comparison, line-ups, paywall as that reader gets them); the page hides the header and newsroom tools and shows a preview banner. Default without a control: standard/neutral AI story for `subscribers`, match graphic.
  - Edited text cites no facts: the editor writes next to the match facts with a live `checkEdit()` (`shared/utils/story-check.ts`: numbers and known people must appear in some fact; quotes/speech/injuries flagged). Advisory, not blocking.
  - `server/utils/story-edits.ts`: controls in `kvcache` (`newsroom:match-stories:<lang>` by match key); HTML sanitised with an allowlist (`xss`) on save and rendered with `v-html`, so keep the TinyMCE toolbar, `valid_elements` and the allowlist in step.
  - Covers: `server/utils/story-images.ts` stores uploads in `kvcache` (`newsroom:image:<hash>`, base64; JPEG/PNG/WebP by magic bytes, never SVG; ≤ 2 MB). `POST /api/newsroom/images` (newsroom), public `GET /api/images/:id` (immutable cache). Covers replace the match graphic in the match page header (`cover` in the match API, shown whatever the story mode) and on front-page cards (`Story.cover`).
  - API `GET/PUT/DELETE /api/newsroom/stories/:id`. The match API sends `story` (`MatchStorySection`; newsroom also gets `hidden`) or, when locked, `locked: ['story', …]` with a teaser (`source: 'newsroom' | 'ai'`). The story endpoint follows the same control (readers always get the published length/tone; other versions, and edited/hidden stories' AI text: newsroom only).
- My teams (`/my-teams`, header "My teams"; hidden for newsroom accounts): favourite teams, leagues and players. `server/utils/preferences.ts` (`kvcache` `prefs:<accountId>`; default = the account's `followedTeams` and their leagues); `GET /api/preferences` (preferences + options; `null` when signed out), `PUT /api/preferences` (subscribers only; unknown choices dropped). Options are mock data: the teams and line-up players of the mock matches (Ipswich, Nott'm Forest) and every competition. Signed out: asked to sign in; free: may choose, "Save" opens the subscription offer; subscribers: saved as they choose. The header no longer links `/status` (still reachable directly).
- Story status (per language), shown and filtered on `/newsroom` with tags for audience (Everyone / Subscribers only) and author ("AI content" or "Author: <editor>"): `live` (published or automatic), `draft` (editor changes saved, not published: `PUT|DELETE /api/newsroom/stories/:id/pending`, `kvcache` `newsroom:pending:<lang>`), `preview` (draft marked ready for review; any newsroom account opens it via `?draft=pending&as=subscriber|free`), `hidden` (hidden in the dashboard: off the front page and the match page's story section). Precedence hidden > preview > draft > live (`storyStatus()` in `story-edits.ts`). Publishing clears the draft; readers always see the live version meanwhile.
- Discussion on match pages (`NewsMatchDiscussion`, `NewsDiscussionComment`; `server/utils/comments.ts`): totals (visible comments, story likes) are public: match page byline and section, front-page cards (`Story.engagement`, one `kvcache` `engagement` map). Subscribers read, post, reply (one level) and like the story and comments; the newsroom also hides / shows / deletes any comment and posts with a "VOZ newsroom" badge; free and signed-out readers get the totals, a read-only preview of the 3 newest top-level comments (`discussionPreview()`) and an invitation. Threads in `kvcache` `thread:<matchKey>` (mock and provider twin ids share one); demo seed `data/comments/<competition>-<id>.json` (server assets `comments`). Plain text only (`cleanCommentText()` in `shared/utils/comments.ts`, tested), 2–1000 characters, one post per account per 15 s. API under `/api/competitions/:competition/matches/:id/`: `engagement` (public), `comments` (GET/POST), `comments/:commentId` (DELETE), `comments/:commentId/{hide,like}`, `like`.
- Newsroom: `/newsroom` (middleware `newsroom`) shows front-page stories with hide/show (`server/utils/moderation.ts`, stored in `kvcache`; `/api/landing` drops hidden stories, `?moderation=all` for newsroom), data-source health and AI cache counts.

## Score semantics (important for the fact ledger)
- `MatchTeam.score` = goals scored in play (regulation + overtime/extra time). Never shootout goals.
- `Match.shootout` records who won a hockey shootout / football penalty shootout (tallies when known).
- Display with `formatScore(m, lang)` (`shared/utils/format.ts`): hockey "4–3 SO" (fi "4–3 vl"), football "1–1, 5–4 pens" (fi "1–1, rp. 5–4"). `displayScore()` gives the shown numbers without text.

## Data gotchas
- Liiga season id = the year the season ends (`2027` = 2026–27); regular season serie `runkosarja`.
- Liiga strings can be mis-decoded UTF-8 ("KÃ¤rpÃ¤t"); `fixEncodingDeep` repairs every Liiga response.
- Liiga team ids contain non-ASCII ("495643563:kärpät"); use ASCII slugs from `shared/utils/liiga-teams.ts`.
- Liiga goal events include ones that did not count (`VT0`, `RL0`) and the shootout decider (`VL`); the
  provider moves them to `notCounted` / `shootout`. Verified: goals match final scores in all 131 finished games.
- football-data v4 `score.fullTime` includes penalty-shootout goals; the provider subtracts them.
- football-data free plan has no goal events, lineups or match stats (`Competition.hasScoringEvents = false`);
  Veikkausliiga needs TIER_THREE (paid).
